# Android visual review checklist

Use an approved synthetic guest/account dataset and the Android build containing these source changes. Record build, device/OS, theme, UI language and actual font/display settings. These checks are pending; no native pass is claimed.

Repeat the main screens in **light/Persian, light/English, dark/Persian, dark/English** at default and maximum text/display size. Include a narrow device where available; 360/390/430px browser checks are useful separately and do not establish Android parity.

| Screen                         | Check                                                                                                                                                                                                                                          |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Home                           | Greeting/artwork leaves space for count and CTA; no decorative progress ring; zero/positive count has the correct action. RTL chevrons, statistics and deck links read naturally.                                                              |
| Settings / account             | One dominant guest sign-in action; subscription is a readable navigation row. Active/unknown/account-error states retain useful actions. No trailing dividers; reminder-time save/cancel remains reachable.                                    |
| Settings / data / about        | Transfer and sync are together; privacy text remains visible. App/version/build are compact and readable.                                                                                                                                      |
| Subscription                   | One page title in the stack; status/dates near the top. Free/Plus/unavailable Premium have distinct weight. All real benefits and availability messages remain.                                                                                |
| Subscription / durations       | Radio selection/check is obvious without implying purchase; total/monthly/discount are distinct and complete. Selection never submits. Guest sign-in and restrictions are near the action.                                                     |
| Subscription / recovery        | With safe fixtures, inspect pending/unknown/expired/provisional/status-read failures. Keep original-account, do-not-pay-again and non-renewal guidance; recovery action remains accessible. No live purchase required.                         |
| Logout                         | Consequences, backup coverage, retention and recovery are separate, always-visible sections. Backup/logout, no-backup/logout and Cancel have clear priority. Cancel changes no data; every action remains reachable with large text.           |
| Deck list / details            | Mixed long names, counts and chevrons remain readable in both directions. Study is dominant; export/edit/delete stay discoverable. Confirmations still explain consequences.                                                                   |
| Card list / details / forms    | Deck typography/alignment and exact content are preserved. Long front/back/examples/phonetics wrap; editor errors retain input and first-invalid focus; keyboard does not cover Save.                                                          |
| Study / order / results        | Order menu stays onscreen and scrolls; long content/reveal and gesture-free answers remain reachable. Physical left-failure/right-success is unchanged. Actual progress/results and explicit review-again remain accurate.                     |
| Analytics                      | Reviewed-today/streak/retention form a clear hierarchy; no-history/null metrics remain truthful. Charts remain chronological LTR, while UI labels respect language.                                                                            |
| Sign-in / signup / reset       | Mode chips and current selection are clear; submit is dominant. All proof/code/cooldown/error/success stages stay readable and recovery works with safe fixtures.                                                                              |
| Name / guest-data gates        | Required fields, preserved input, preview/blocker/conflict guidance and copy/resume remain readable. Discard is secondary but unmistakably destructive, with explicit confirmation.                                                            |
| Appearance / language / speech | Current selection is clear; labels/checks follow language. Saving/error/busy and unavailable-voice guidance remain readable. Changes persist under existing scope rules.                                                                       |
| Cloud / backup                 | Sync, pending/conflict recovery and backup are distinct tasks. A verified backup can coexist with a failed status refresh. Dates/expiry/coverage and all safe recovery choices remain visible.                                                 |
| Transfer / import preview      | Import/export, format selection, preview consequences and receipts remain distinct. Long issues/partial results scroll; save/share/retry/close remain reachable.                                                                               |
| Vocabulary / pronunciation     | Suggestions, no-result/offline/error/manual-entry and speech recovery retain clear actions; user content is not clipped or changed.                                                                                                            |
| Dialogs / errors / startup     | Check all portal text, overlays and controls in dark mode. Verify scroll, focus entry/restoration, Android Back, busy protection, retry and retained credential recovery. No duplicate announcements or disappearing essential guidance.       |
| Shared controls / layout       | Ordinary cards feel quieter than elevated dialogs; section gaps form a readable rhythm. Buttons remain comfortable targets, long labels wrap, focus/pressed/disabled/selected states are distinct. No clipped content or unreachable controls. |

Use TalkBack to check control name/role/state, radio selection, reading order, dialog containment and recovery announcements. Verify Myket handoff/recovery, Android notifications, native SQLite/SecureStore and restart/interruption behavior separately with approved fixtures. A visual review does not close those functional gates.

For a defect, record screen/state, theme/language/text setting, expected versus actual behavior and a synthetic-data screenshot. Do not accept eye flow, contrast or accessibility based on source alone.
