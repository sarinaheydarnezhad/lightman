## Accessibility source findings

A01 P1: Input's English-only error prefix is confirmed (W02). A02 P2: SettingsSwitch exposes checked/busy but omits disabled from its explicit accessibilityState while its Pressable can be disabled; SettingsRow similarly disables interaction without an explicit disabled state. Verify actual native accessibility output before asserting TalkBack behavior; propose equivalent state semantics. A03 verification: FeedbackModal/ConfirmationPanel set focus on show but do not explicitly restore trigger focus in their own code; platform behavior may supply it. Treat restoration as unverified, not a proven failure. Existing gesture-free StudyControls, allowFontScaling, reduced-motion flip alternative, hidden reverse face and chart labels are useful source support, not compliance evidence.

Unrendered contrast calculations for 48 semantic-text/background combinations are retained in `evidence/baseline/token-contrast.json`. They do not cover every foreground pairing, opacity, actual portal inheritance, pressed/disabled controls or effective rendered backgrounds and are not contrast passes for the app.

## Design-system disposition

Retain canonical tokens `shared/theme/values.json`, typed tokens, NativeWind mappings, Vazirmatn assets and explicit persisted light/dark choices. Existing semantic roles, scalable SVGs, minimum control sizes, responsive study controls and reduced-motion alternatives are useful foundations. No evidence justifies replacing the stack or identity. Add role-based composition standards rather than a second palette. Button tertiary/ghost appearances currently coincide; clarify intentional API distinctions before expanding variants. Success/error/warning/info roles must be evaluated on effective backgrounds, including opacity and portals. Source review cannot establish actual native contrast or optical balance.
