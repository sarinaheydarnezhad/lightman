## Protected behavior and contract tests

Free limits remain one active deck/50 active cards under actual counting rules; data over limits is retained. Plus availability/prices are server-authoritative; Full/Premium availability must be truthful. Phone/password login and purpose-bound signup/reset proofs, session revocation and credential clearing remain unchanged. Guest transfer remains explicit additive copy with isolation/journal/preview checks. Sync keeps expected versions, operation UUIDs, immutable history, durable outbox and explicit conflicts. Backup creation requires verified owned artifact/expiry/cursor; status-refresh failure is distinct from creation failure; backend restore capability does not imply app restore. Do not rotate/delete key rings, change retention or silently delete pending/completed artifacts. No learning algorithm, user-content normalization or security rule change is authorized.

Relevant later backend suites in `Backend/backend/Flashcards.Tests/`: PhoneAuth/AuthRecovery/PhoneVerificationSecurity/PhoneOtpConcurrency; MyketPayment/MyketVerifier/Subscription; GuestMigration; Sync/ConcurrencyLimit/Persistence; BackupFlow/BackupRecovery/BackupRestore/BackupLifecycleConcurrency/Sm2Backup; SchedulingContract/SchedulingVectors; CardContentContract/CardContentBackup; MobileCloudFlow integration with explicit frontend harness configuration. Use isolated providers; SQLite tests cannot establish SQL Server locking/recovery. Backend tests were not run in this assignment.
