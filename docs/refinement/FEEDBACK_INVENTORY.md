Root issue F01 (P1): `Input`, `ErrorState` and consumers delegate diverse contexts to a single queued modal; feedback surface is selected by shared component rather than impact/action requirements. F02 (P1): dismissing context-essential information can leave only a retry button or reopen action, increasing recovery discovery cost. F03 (P1): multilingual generic error fallbacks remove actionable detail. These are source mechanisms; interruption frequency and user impact need runtime validation. Do not delete queue/eventKey machinery until producers are migrated deliberately. Success/error tone must not be inferred merely from presence of a message.

The appended site ledger includes each statically located FeedbackModal, ConfirmationPanel, Modal, ErrorState, LoadingState, EmptyState, live-region and announcement producer. The dictionary ledger supplies potential message variants; unused keys do not imply actual events. Consumer-specific execution, OS/provider prompts, concurrent operation timing and account transitions remain unverified. No claim of exhaustive real-world event occurrence is made.

## Explicit guest discard clarification

`guest-data-screen.tsx` discard() calls `guestTransfer.discard(preview)` only through a named irreversible ConfirmationPanel. Keep this destructive guest-only choice distinct from additive copying and from unsupported destructive account replacement. Preserve preview validation, in-progress restrictions, failure recovery and no implicit discard. This path requires its own confirmation and critical-flow fixture; successful test names do not prove native safety.
