# App feedback

Updated 2026-11-15 under owner-approved refinement decision D-28. The previous modal-for-all policy is superseded by [the contextual presentation policy](refinement/FEEDBACK_PRESENTATION_POLICY.md). Tone does not choose the surface; the task, certainty and recovery requirements do.

- `Input` keeps localized field errors beside the field and in its accessibility hint. Correcting the field clears validation. Card/deck required-field validation focuses the relevant input; invalid content is not submitted. Validation does not dismiss the keyboard or open a second modal.
- `ErrorState` renders a persistent title, explanation and Retry. Resource failures have no dismissible overlay; retry remains in the unavailable section. Existing resource hooks still decide loading/data/error availability; no new stale-cache behavior is claimed.
- `FeedbackNotice` is task-owned, persistent and nonmodal. It neither queues nor interrupts other tasks, changes focus, starts a timer, acknowledges an operation or recovers automatically. Empty/disabled notices render nothing. The producer clears/replaces state at its existing next-attempt, outcome or unmount boundary. Optional Close is for explicitly dismissible local information; critical recovery has no Close/timer. Busy retry actions are disabled. The caller's operation guard remains authoritative.
- Android/web notice text uses a polite live region. iOS announces once per active event; explicit `eventKey` identifies repeated distinct outcomes. Language wording changes do not replay the same keyed event. Clearing the event resets announcement eligibility. Verify real native speech; mock tests do not establish spoken behavior.
- Forms, preferences, vocabulary/pronunciation, study start/save, free-limit restrictions, subscription/payment uncertainty, guest previews/conflicts and cloud/backup/file feedback use contextual states. Ordinary preference success uses the changed selection. Study completion retains its results screen. Card-create confirmation remains useful because the form resets for another card.
- Financial pending/checkout restrictions stay visible, with existing original-account/Myket/one-hour recovery terms and Recover purchases. A duration choice is distinct from submission. No transient message verifies entitlement; only existing server-authoritative handlers can do so.
- Sync conflict choices and failed-operation retry remain visible together. Failed resolution keeps choices available. Cloud local state is keyed by phase/owner/revision; unmounted responses cannot populate the new screen. Sync UUID/version/outbox/epoch behavior is unchanged. Routine account IDs/cursor are replaced by a meaningful pending-change status in this screen.
- A verified backup receipt and later status-refresh error can coexist. Refresh is distinct from creating another backup; no failed creation is inferred from an independent read failure. Restore remains unavailable in the app. Import shows its saved/partial summary in a scrollable result view; approval, cancellation and data mapping are unchanged.
- `ConfirmationPanel` and full-screen name/guest gates remain consequential/ownership surfaces. Errors stay inside the existing dialog; busy Back/cancel/duplicate-submit guards remain. Destructive styling is default for existing destructive callers; non-destructive confirmations can pass `destructive={false}`.
- `FeedbackModal` remains for the global signed-out/credential receipt in `logout-notice.tsx`, including credential-clear recovery. Its original queue, event identity, enabled/dismissal semantics and retained retry after closing are unchanged. Unmount removes queued notices. Closing a receipt does not clear credentials, verify backup, revoke a session or resolve a conflict.

Keep essential page content inline: editable fields, study questions/results, charts, current account/subscription/backup status, loading/progress indicators, and explanations required to make a safe choice. These are not transient notifications. Study completion still shows the result screen first; its Done action opens analytics.

See [FEEDBACK_LIFECYCLE.md](refinement/FEEDBACK_LIFECYCLE.md) for producer-specific contracts. Native focus restoration, effective rendered theme inheritance, large text and screen-reader behavior remain unverified while ADB/browser rendering are blocked.
